# 编辑功能方案（高性能路线）

目标：在现有本地 Markdown 阅读器上增加**完整的编辑能力**，同时保持"秒开秒关、大文档不卡、多窗格同屏"的既有性能特征。

---

## 1. 现状与约束

**当前是纯只读。** 证据：

- Rust 侧注册的命令只有 `read_markdown` / `fs_list_dir` / `fs_pick_folder` / `fs_pick_markdown_file` / `search_folder` / `session_save` / `session_load` / `open_external` / `fs_reveal` / `startup_ms` / `perf_log` / `card::*`（`src-tauri/src/main.rs:181`），**没有任何写 `.md` 的命令**；`card.rs:102` 的写盘只用于导出图片。
- 前端依赖里没有任何编辑器（无 CodeMirror / Monaco / ProseMirror / Milkdown），也没有正文 `contenteditable` 或 `textarea`（`ContextMenu.tsx:41` 只是跳过输入焦点）。
- 正文是 comrak 解析出的 HTML 一次性 innerHTML 注入，任务列表勾选框也是 comrak 渲染的 disabled 元素。

**必须继续满足的既有约束：**

- 解析在 Rust 后台线程，HTML 字符串一次交给 WebView；正文禁止用 React 组件树渲染。
- `(路径, mtime)` 为 key 的 LRU 缓存，命中零解析（`markdown.rs:47`，容量 64）。
- >1MB 文档分块注入 + 虚拟滚动；未激活窗格冻结（不挂 DOM，`MarkdownPane.tsx`、`CardPanel.tsx`）。
- 会话持久化布局树、每窗格滚动位置、主题、窗口尺寸。
- 依赖只用宽松许可（MIT / Apache-2.0 / BSD）。

---

## 2. 总体原则

> **编辑器只负责"输入"，渲染管线不动。**

预览继续走 comrak + innerHTML 注入，因此第 1 节列出的性能资产全部复用，而不是换一套渲染栈。编辑引入的新增成本只集中在三处：编辑器自身、增量重解析、保存链路。

---

## 3. 编辑器选型

| 方案 | 许可 | 结论 |
|---|---|---|
| **CodeMirror 6**（`@codemirror/*`、`@lezer/markdown`） | MIT | **首选**。视口渲染（仅可视行进 DOM）、Lezer 增量解析、rope 文本结构；多光标、搜索替换、事务化撤销历史现成；10MB 级文档依旧顺滑 |
| Milkdown（ProseMirror + remark） | MIT | 需要所见即所得时选它（markdown-first 模型）；但 ProseMirror 文档模型在 1MB+ 明显退化，建议限定 <300KB 文档或做成可选模式 |
| ProseMirror 裸用 / TipTap | MIT | 不优先：需要自己写 markdown 序列化与 schema，工作量大且易"保存后格式被改写" |
| Monaco | MIT | 不选：体积大、面向代码、无 markdown 语义 |
| 受控 `<textarea>` + React 重渲染 | — | **禁止**：每次按键整棵子树重渲染，大文档必卡 |
| 自研 `contenteditable` | — | **禁止**：选区、输入法、撤销、粘贴全是坑 |

许可核对：CodeMirror 6、Lezer、Milkdown、ProseMirror 均为 MIT，符合"只用宽松许可"的项目规则。

## 4. 架构设计

### 4.1 面板形态

新增一种 dockview 面板组件 `edit`，与 `doc`（阅读）、`card`（卡片导出）并列。同一文档三态可切换：**编辑**（仅编辑器）/ **分栏**（编辑器 + 预览）/ **阅读**（仅预览，即现状）。

- 布局、拖拽、分屏、最大化、冻结、会话恢复零改动——都是既有的面板机制。
- 同一路径允许同时存在 `doc:` 与 `edit:` 面板（分栏即两态合一，不必开两个面板）。
- **面板内不放工具条**（2026-09-18 按反馈调整）：形态切换（源码/分栏/预览）、保存状态、换行/BOM 徽标
  都放既有的顶部工具条；从阅读态点形态按钮时，若当前文档还没有编辑面板就顺手开一个，形态记进会话。
  面板内只留冲突横幅与保存失败提示这类"必须立刻处理"的现场动作，不做常驻控件。

### 4.2 数据流（性能核心）

```
按键 → CodeMirror 事务（本地，无 IPC）
     → 计算受影响顶层块范围（按空行/块边界切片）
     → 防抖 ~120ms，只把「块范围 + 新文本」发给 Rust
     → Rust 只重解析这些块（comrak 按块切片解析）
     → 返回块 HTML → 前端按 data-block-idx 局部替换
```

三条硬规则：

1. **不回传全文**。前端持有文本缓冲（CM6 Doc），IPC 只传变更块。
2. **不整篇 innerHTML 重写**。整篇重写会丢滚动位置与选中态；只替换受影响块。
3. **打字期间预览降级**：mermaid / KaTeX 等重增强在空闲 300–500ms 或失焦后再补跑（现有 `enhance.ts` 已是按块增量，扩展为"块替换后仅增强新块"）。

### 4.3 IPC 草案（新增命令）

```rust
// 完整读（复用现有 read_markdown：分块 HTML + chunks 元信息 + toc + sourcepos）
read_markdown(path) -> { html | chunks, toc, size, parse_ms, from_cache }

// 块级增量重解析：仅当文档已缓存时可用
render_blocks(path, ranges: Vec<(usize, usize)>, text: String) -> { blocks: Vec<{ idx, html }>, parse_ms }

// 保存（原子写：临时文件 + rename，与 session.rs:20 同策略）
write_markdown(path, text, expect_mtime_ms: Option<u64>) -> { mtime_ms, bytes } | Err(Conflict)
```

前端封装加到 `src/lib/ipc.ts`，与现有风格一致。

### 4.4 缓存与失效

- 保存成功后 mtime 变化 → `(path, mtime)` 键自然失效，下次 `read_markdown` 重新解析（既有逻辑无需改动）。
- 增量路径不走 LRU：它直接对传入文本切片解析，返回块 HTML，由前端拼接进当前 DOM；完整缓存留待下次整篇读取时刷新。
- 同一文档多窗格同开时：编辑面板保存 → 广播 `app:doc-changed{path, mtime}` → 阅读面板按需重读（冻结中的窗格只标脏，激活时再读）。

### 4.5 冻结与会话恢复

- 面板不可见时销毁 CM6 `EditorView`（不挂 DOM），把 `EditorState.toJSON()` 与视口信息存入面板级缓存（与 `scrollMap`、`chunkHtmlCache` 同层），可见时 `EditorState.fromJSON` + 恢复滚动。
- 会话仍只存布局树与滚动位置，不存文档内容（内容永远以磁盘为准，避免"会话里是旧文本"的陷阱）。

### 4.6 源码 ↔ 预览的映射（已有资产）

`data-sourcepos="起始行:列-结束行:列"` 已经在写（`markdown.rs:134`），前端已有解析器（`MarkdownView.tsx:410`）。因此：

- 滚动联动：预览滚动 → 取顶部块 sourcepos → CM6 `dispatch({scrollIntoView})`；反向同理。
- 点击正文块 → 光标跳到对应源码行；点击源码行 → 预览滚动到对应块。
- 不需要额外解析器，也不需要维护第二套映射表。

### 4.7 保存链路之外的一致性

- **原子写**：临时文件 + rename；写失败不留半截文件。
- **自动保存**：空闲 ~1s 防抖 + `Ctrl+S` 立即保存；失去焦点、切换标签页时立即保存。
- **冲突检测**：保存前比对 `mtime`，不一致则提示"磁盘上已改动"，给出「覆盖 / 重新载入 / 另存为」三个选项，绝不静默覆盖。
- **换行与 BOM**：读入时记录原文件的换行风格（CRLF/LF）与 BOM，写回保持一致，避免"只改一个字整个文件都变"。
- **外部改动监听**：Rust 侧 `notify` 监听当前文档（watch 父目录以免改名失效、80ms 去抖、事件带 mtime）；
  阅读面板热刷新，编辑面板提示冲突。已实现，见阶段 2 验收报告 S5。
- **撤销/重做**：走 CM6 事务历史，不自己存全文快照。

## 5. 阶段拆分与验收口径

每阶段的验收都在**真实应用入口**做，用现有 CDP 验收台（`scripts/cdp.mjs`）与 `perf.log` 取实测数据。

> **进度（2026-09-18）**
> - 阶段 1 **已完成并验收**：`node scripts/edit-probe.mjs` 24 项通过 / 0 项失败，实测见 `docs/编辑功能-阶段1验收报告.md`。
> - 阶段 2 **已完成并验收**：`node scripts/edit-probe2.mjs` 11 项通过 / 0 项失败（S1 局部替换 / S2 联动与跳转 /
>   S3 大文档切片 / S4 增强降级 / S5 外部改动监听），实测见 `docs/编辑功能-阶段2验收报告.md`。
> - 阶段 3（WYSIWYG）未开始，仍为可选项。

### 阶段 1 — 编辑器面板 + 分栏预览 + 保存链路（性价比最高）

交付：`edit` 面板（CM6 源码编辑器）、分栏预览复用现有管线、`Ctrl+S` 与空闲自动保存、冲突检测、换行/BOM 保持。

验收（全部要实测数据，不接受"看起来没问题"）：

| 项 | 口径 |
|---|---|
| 打开 2MB 文档进入编辑 | 可交互 ≤ 1s；键入 100 字符期间无长帧（CDP `fps` 探针，长任务 0 次） |
| 键入延迟 | 单键 → 预览块更新 完成时间 P95 ≤ 150ms（含 IPC 往返） |
| 往返数据量 | 单键 IPC 载荷 ≤ 32KB（2MB 文档），不随文档体量增长 |
| 保存正确性 | 保存后文件与编辑器缓冲逐字节一致；CRLF/LF 与 BOM 保持原样 |
| 原子性 | 保存过程中强杀进程，磁盘上不存在半截文件 |
| 冲突 | 外部改文件后保存 → 出现冲突提示，三个选项行为正确，不静默覆盖 |
| 缓存链 | 保存 → 另一阅读窗格内容刷新；再开同文档命中新 mtime 的缓存 |
| 冻结恢复 | 切走再切回编辑面板，光标位置与视口恢复；冻结期间不挂 DOM |

### 阶段 2 — 块级增量 + 双向联动

交付：块级增量重解析、`data-block-idx` 局部替换、sourcepos 滚动联动与双向跳转。

验收：

| 项 | 口径 |
|---|---|
| 局部替换 | 键入前后 DOM 中未受影响块的元素身份不变（对象引用对比） |
| 滚动联动 | 双向联动定位误差 ≤ 1 个块 |
| 大文档 | 1MB 文档键入时只重解析受影响块（`render_blocks` 返回的 parse_ms ≤ 5ms） |
| 增强降级 | 打字期间不触发 mermaid 重渲染；空闲后补齐且结果与整篇渲染一致 |

### 阶段 3（可选）— 所见即所得模式

交付：Milkdown 模式的四态切换（源码 / 分栏 / 预览 / WYSIWYG）。

验收：<300KB 文档下键入无掉帧；对既有 8 个卡片模板与验收样例的 Markdown 往返保存后，**格式零改写**（表格、脚注、内联 HTML、代码块围栏抽样比对）。

## 7. 风险与取舍

1. **定位漂移**：阅读器变编辑器后，"未激活窗格不挂 DOM""虚拟滚动""缓存失效"三条链都要在新场景下重新验证（尤其保存 → mtime 变化 → 重解析）。
2. **WYSIWYG 的语义损耗**：复杂 Markdown（表格、脚注、内嵌 HTML）在 WYSIWYG 下容易"保存后被改写"。因此阶段 3 是可选，且默认模式仍是源码 + 预览。
3. **增量解析的边界**：块级切片在"跨块结构"（列表嵌套代码块、引用内多段、表格跨行）上需要谨慎定义块边界；实现时以"保守扩大重解析范围"换取正确性——宁可多解析一块，不可渲染错。
4. **多窗格同文档**：同文档多窗格同开时，编辑保存与阅读刷新需要显式广播，避免两个面板各自持有一份过期 HTML。

---

## 8. 明确的非目标

- 不做多人协作 / OT / CRDT（未来若要，CM6 有成熟的 yjs 接入路径，但不在本方案范围）。
- 不做 Git 集成、不做 diff 视图。
- 不改动现有解析与渲染管线的技术选型（comrak / innerHTML / LRU / 虚拟滚动全部保留）。
- 不在阅读模式下暴露任何可编辑表面（保持"读"的纯净与冻结策略）。
