# Local read-aloud implementation and acceptance

The toolbar owns playback independently of the Markdown pane. ZipVoice-Distill INT8 runs on the CPU through sherpa-onnx 1.13.8 and native ONNX Runtime. Model loading starts only after an explicit read-aloud action. The engine is reused for the application session and uses two inference threads. There is no Python or cloud service in the production path.

## Development setup

Run `powershell -File scripts/setup-readaloud.ps1`. This reuses the existing official ZipVoice archive/model and Vocos when available, otherwise downloads the official files once, validates required assets, copies the tracked accepted reference, and prints the configured model directory. Choose that directory under 设置 → 阅读 with “选择本地模型文件夹”. This is an explicit setup operation, not an application-startup download. Model and native libraries are not committed. Cargo obtains the official sherpa-onnx 1.13.8 Windows shared libraries at development compilation and copies the DLLs next to the development executable. Packaging and installation of these DLLs have not been tested or authorized.

The UI offers one accepted conversational female voice, speed, previous/next paragraph, pause/resume/stop, a visible-paragraph starting point, optional following, and playback-derived paragraph highlighting. Speed and the selected model directory persist; legacy voice IDs normalize to the single supported voice; playback never resumes automatically after startup. Speed, follow, and model-folder settings are on 设置 → 阅读, while playback controls and “从这里朗读” remain in the toolbar.

## Boundaries

Text comes lazily from complete raw rendered chunks, including chunks outside the virtual viewport. Headings, paragraph text, list items, quotes, and link labels are included. Fenced code, tables, images, math, and Mermaid are skipped. At most two sentence units are outstanding. The native synthesis and audio workers use bounded channels, and PCM never travels through the WebView. Stop immediately stops the native audio sink and invalidates queued/in-flight work by generation token. ONNX cancellation is cooperative at the synthesis callback; an inference call itself is not claimed to be immediately interruptible.

The source file remains watched while its pane is hidden. Closing the source panel stops playback; tab changes and pane hiding do not. Entering settings pauses. A source-change event invalidates the snapshot and requires a new explicit start.

## Original Kokoro real engine evidence

The isolated development application used `com.freemdown.readaloud.dev`; the installed user instance was preserved. The production queue generated Chinese audio and sent it to the native playback sink. The first phrase produced 44,828 samples at 24 kHz (1.867 s), taking 2,672 ms including lazy engine loading. The second sentence produced 62,678 samples (2.611 s), taking 1,187 ms with the engine warm. Playback start/done events arrived from the audio worker, not synthesis completion. These figures came from the i7-12700KF host and do not establish ordinary-laptop performance. Waveform generation and device submission do not establish subjective naturalness or that the user heard it.

The initial smoke script used a forward-slash document path while the visible panel used a backslash path. A subsequent test used the actual active-panel path and verified toolbar start, playback-derived highlighting, a 600 ms pause without advancing, resume/next paragraph, the actual reading-document label while another tab was focused, settings pause across pane unmount/remount, and stop clearing highlighting in 9.2 ms. A separate source-lifecycle check verified that modifying the hidden source invalidated the snapshot, and closing its panel stopped playback. The Primary also personally observed the independent window, controls, document, and stop behavior through ComputerUse. The Primary cannot directly hear system-speaker audio.

A 1,229,609-byte document with 38 raw chunks was scrolled for three seconds before and during native synthesis/playback. Baseline: 117.05 FPS, one frame above 32 ms, maximum gap 33.4 ms. Reading: 116.49 FPS, two frames above 32 ms, maximum gap 49.9 ms. These are host-specific observations, not ordinary-laptop guarantees. The native process working set was approximately 615 MB after model loading.

For subjective sound acceptance, the same production synthesis worker saved one real Chinese prose WAV under an explicitly set debug-only environment variable, `FREEMARKDOWN_TTS_DEBUG_WAV`. It does not add a product export feature or save audio during ordinary usage. The artifact is `.verify/tts/中文朗读-正文试听.wav`, 861,968 bytes, 430,962 samples at 24 kHz, lasting 17.956 seconds. The cold synthesis including model loading took 11,544 ms. Its text is: “夜里十一点，窗外的雨还没有停下来，林远把书翻到昨天折起的那一页，忽然发现，自己记住的并不是那些复杂的道理，而是一个很简单的提醒：遇到难题时，先把眼前能够做的一小步做好。” Native playing and done events were observed; playback was stopped afterward.

The user rejected the Kokoro voice because it sounded emotionless and staccato. The original model choice has failed subjective acceptance; functional test results do not establish natural speech. A native Qwen3-TTS 0.6B CustomVoice Serena prototype was also auditioned and rejected. Its isolated Q4 CPU run generated 18.857 seconds of audio in 57.326 seconds (RTF 3.040), so it also failed continuous realtime performance. Neither candidate is accepted as the final voice. Further voice evaluation is isolated under `.verify/tts`; the production backend was subsequently replaced by the accepted ZipVoice voice as recorded below. No release/install or ordinary-laptop acceptance is claimed.
